A portfolio treated like a product, not a profile page.

This site is a personal project built with the same care as a product surface: bilingual by design, static-first by default, and intentionally shaped around editorial pacing instead of generic portfolio blocks. The goal is to present current work, long-term craft, and personal systems in a way that feels precise, durable, and unmistakably Apple-aware without copying Apple assets.

Product

The site was designed as an editorial product, not a résumé dump.

#

The structure prioritizes who I am professionally today, then expands into deeper layers of projects, technical profile, writing, reading, sports, and broader personal systems.

Present first

The homepage is centered on current role, current work, and a clear technical profile before opening into deeper archive and personal sections.

  • The site answers the present-tense question first.
  • Secondary areas still exist without competing with the core story.

Editorial pacing over generic components

The layout uses restrained spacing, cinematic hierarchy, and progressive reveal rather than a template grid of interchangeable portfolio blocks.

  • The design aims for calm precision instead of busyness.
  • Motion supports storytelling rather than decoration.

A durable personal surface

The product is meant to stay maintainable as the career evolves, with room for deeper projects, writing, reading, and manual curation over time.

  • The architecture is built for long-term ownership by one engineer.
  • The public surface can evolve without drifting into complexity.
System

The architecture stays lightweight without becoming brittle.

#

The public output is plain static HTML, while a local Swift generator handles bilingual routes, metadata, content reuse, and project-detail expansion.

One source of truth

Localized copy, routes, metadata, and content structures live in a single content source that the generator turns into final pages.

  • This limits duplication across English and French.
  • It keeps content changes separate from rendering concerns.

Static output, modern feel

The site avoids frontend framework runtime costs while still supporting theme switching, reveal behavior, and project storytelling through small progressive-enhancement layers.

  • Core content remains available without JavaScript.
  • Interactive behavior is deliberately minimal and recoverable.

Privacy and operational simplicity

No trackers, no external font loading, and no live backend are required for the main product experience.

  • The default posture favors user privacy and predictable performance.
  • Deployment remains compatible with simple static hosting.
Execution

The project is also a testbed for taste and long-term maintenance.

#

Beyond the visible pages, the site is an ongoing exercise in content modeling, bilingual parity, documentation discipline, and shipping a polished experience with minimal moving parts.

Documentation kept in step

README, architecture notes, and agent handoff guidance evolve with the implementation so another pass can continue cleanly later.

  • The project is structured for continuity, not just launch.
  • Documentation is treated as part of the product system.

Manual curation where it matters

Books, sports, trophies, and writing are modeled as product surfaces first, with manual data expected before any live integration is considered.

  • The site avoids unnecessary automation.
  • Static-first choices stay intentional rather than temporary.

A personal benchmark

The site sets a public quality bar for how I think about design, architecture, privacy, and product clarity when I build software.

  • The implementation is itself part of the portfolio.
  • Taste and technical discipline are both visible outputs.
